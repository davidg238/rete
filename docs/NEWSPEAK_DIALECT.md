# ns-oevm — a Newspeak dialect (intentional differences from full Newspeak)

> **Purpose.** ns-oevm is a *dialect* of Newspeak — a deliberate subset targeted at
> embedded scripting on a JIT-less bytecode interpreter (st-zephyr scope), making
> minimal, initial compromises to respect limited memory and CPU. This document is
> the single, append-only record of
> every place ns-oevm intentionally diverges from full Newspeak semantics, **why**,
> and the **trigger** that would make us revisit. Add an entry whenever a step
> introduces a new divergence; never silently break the language.

## Framing & background — why these compromises, in this order

**The goal.** ns-oevm aims at one thing: a *modern* embedded scripting language for
memory- and CPU-constrained targets — where "modern" means object-**capability**
security, **fibers** for concurrency, and **over-the-air / in-image debug**, all on a
JIT-less bytecode interpreter that solidifies to static C (Path A) or a frozen image
(Path B). The deviations in the table below are not features we ran out of time for;
they are a deliberate ordering of *which costs to pay now and which to defer*, chosen so
that the expensive, hard-to-reverse part is the part we pay for up front.

**Two axes, opposite reversibility.** Where we diverge from full Newspeak falls on one
axis; where we hold the line falls on another, and the two have opposite reversibility
profiles:

- *The foundational axis (kept — irreversible if skipped).* No global namespace (#8/#9),
  modules as first-class parameterized objects (`usingPlatform:`), stratified execution
  (#14), and a confined capability for every privileged surface — native I/O (#13),
  reflection (#15), the debugger (#16). **Object-capability security and
  no-ambient-authority must be designed in from the first line.** You cannot bolt
  confinement onto a system that already assumed ambient globals and ambient reflection —
  that is precisely why retrofitting capabilities onto Smalltalk or Python fails. This is
  the costly, hard-to-reverse half, and it is the half we paid for up front.

- *The additive axis (deferred — reversible).* Everything we gave up clusters into **one**
  coherent feature-family: *late binding of class references* — virtual classes (#1), the
  mixin application that composes them (#2), and the auto late-bound class-slots that
  express them (#6). It is deferred because (a) it is pervasive overhead a JIT-less
  interpreter cannot absorb — production Newspeak leans on Truffle/Graal to make virtual
  class lookup free — and (b) it is **additive**: static binding is a *special case* of
  late binding (a class-slot that is never overridden behaves identically), so nothing
  written against the static dialect becomes *wrong* when virtual classes are later added.
  The revisit triggers on #1/#2/#6 all describe the same restoration on the same
  substrate (vtables, `delegate` pointer, `OP_NEW`).

**The progression.** Read the row numbers as a build order — each step a precondition for
the next. Library shaping under a strict capability discipline (#3–#12) culminates in the
first confined native capability, `Serial` (#13); base-level execution is then stratified
off the meta-protocol so reflection becomes *confinable* (#14); reflection is lifted into
a single confined `mirror` capability (#15); and a real interactive debugger is layered on
that grant with **zero new ambient surface** (#16). Capabilities are the through-line:
each privileged subsystem is one C module behind one receiver-identity hook, never
re-monolithising `dispatch.c`, never granting ambient authority. The debugger (#16) is the
proof the foundation holds — the canonical privileged subsystem, built entirely from
confined parts, and (measured) imposing ~0 cost when its gate is off.

**The posture going forward.** This file is a demand-driven ledger, not a list of regrets.
Because the foundational decisions went the Newspeak way and only the additive one was
deferred, the path from *"a capability-secure Newspeak with a Smalltalk-shaped object
model"* to *"full Newspeak"* is open and additive — it strands no existing code. When real
code wants the deferred dynamism (a subclassable module, a mixin), the matching trigger has
fired. The first friction to surface, though, will not be #1 — it will be the ergonomic tax
of threading `platform` and hand-writing class accessors (#6/#9); that is independently
cheap to fix, and the fix (auto class-slots) is itself step one toward virtual classes.
The principle is constant: **pay for foundations up front, buy dynamism on demand.**

| 14 | **Base-level execution uses dedicated bytecodes, not reflective sends** (stratify-execution step) | Block `self` access, captured-variable reads/writes, closure creation, and NLR sender-walk are ordinary reflective sends (`home`, `regAt:`, `regAt:put:`, `createClosure:`, `sender`) dispatched through the interpreter. | These four operations are handled by dedicated opcodes: `OP_LD_LEXICAL` (block `self` and captured-var read), `OP_ST_LEXICAL` (captured-var write), `OP_CLOSURE` (closure creation), `OP_LD_SENDER` (NLR sender-walk). | 19 | **Control-flow combinators are compiler-lowered bytecode, not reflectively-sendable methods; non-literal combinator arguments evaluate lazily** (de-recursify Phase 1–2) | `ifTrue:`/`ifFalse:`/`ifTrue:ifFalse:`/`and:`/`or:`/`to:do:`/`to:by:do:`/`whileTrue:`/`whileFalse:`/`timesRepeat:`, and the **unary** `whileTrue`/`whileFalse` (no colon), are ordinary keyword/unary messages dispatched to real methods on `Boolean`/`Integer`/`Block` — reflectively sendable (`aBool perform: #ifTrue:withArguments:`), and their arguments are evaluated **eagerly** before the send. | these selectors are lowered by the compiler to branch/loop bytecode driving `OP_BLOCK_INVOKE` (0x16), and the recursive C fallback primitives (`PRIM_ifTrue`/`ifFalse`/`ifTrueIfFalse`/`and`/`or`/`to_do`/`to_by_do`/`timesRepeat`, plus the `whileTrue:`/`whileFalse:` **and** the unary `whileTrue`/`whileFalse` `BytecodeClosureVtable` intercept loops) are **deleted**. Phase 1 lowered the if-family/`and:`/`or:`/`to:do:`/`to:by:do:`/`whileTrue:`/`whileFalse:` set; Phase 2 completed it by lowering the two that were missed (`timesRepeat:` and the unary `whileTrue`/`whileFalse`) before flipping the engine. Consistent with standard Smalltalk-family practice (control-flow selectors are always compiler-special-cased); no in-tree program uses the affected reflective / compound-arg / non-SMI-step patterns (suite 81/0/6 both paths, grep-clean across ns-tests/ns-oevm/ns-posix). | a real need to reflectively `perform:` a control-flow selector, to pass a side-effecting compound expression as a combinator argument, or a non-integer `by:` step — restore by adding thin image-level `Boolean>>ifTrue:` / `Integer>>to:do:` / `Integer>>timesRepeat:` methods (which themselves lower via `value`). |

**De-recursify Phase 3 (fibers + demolition, 2026-07-01) — no new row, intentionally.**
Phase 3 swapped the fiber-switch mechanism from a `ucontext`/reload-hijack pair to a
single universal C-stack activation (one mechanism, all targets) and deleted the
conservative C-stack GC scan in favor of fully precise rooting. Neither change
touches the language, bytecode set, or any `.ns` facade — `fiberSwitch:value:`'s
signature and observable semantics are unchanged, no opcode was added or removed,
and no capability grant surface moved. Row 19 (Phase 1–2) remains the only
de-recursify-rewrite entry in this table; the absence of a row 20 for Phase 3 is
confirmed intentional, not an oversight.

## How to use this file
- One row per deviation. Keep the **Why** and **Revisit trigger** concrete.
- When a future step *removes* a deviation, strike the row and note the step that closed it (don't delete the history).
- Cross-reference the spec/section that ratified each decision.

## Compared to Smalltalk

The table above records where this dialect *subsets* Newspeak. This section is the
counterpart: the Newspeak properties we deliberately **keep** because they are
genuine improvements over Smalltalk-80, regardless of the embedded subsetting.
The tone here is explanation, not advocacy — these are simply the things Newspeak
does differently from Smalltalk, and why they matter for this project. (Most are
about *structure and deployment*, not expressiveness: Smalltalk-80 remains more
dynamic and more interactive, by design.)

- **No global namespace.** Smalltalk-80 keeps every class in one mutable
  `Smalltalk` system dictionary, so any method can name any class (`Array`,
  `Transcript`) directly — ambient authority everywhere. Here, every name is
  reached through a handed-in object (`platform <Name>`). A class can only touch
  what it was given. Consequences: capability scoping (least privilege), no global
  name collisions, and trivial testability (inject a mock `platform`). Deviations
  #8 and #9 are us enforcing this *more* strictly than Smalltalk, not relaxing it.

- **Modules are first-class parameterized objects** (`Kernel usingPlatform: platform`).
  A module is an *instance* parameterized by its dependencies, not class-side
  methods reaching into globals. Dependency injection *is* the structuring
  mechanism. A practical payoff falls out of this plus "no global namespace":
  **two module instances can be parameterized with different library
  implementations — even different versions of the same library — and coexist in
  one VM without colliding**, because neither reaches its classes through a shared
  global; each reaches them through its own module. Per-target variant selection
  (a growable `OrderedCollection` on Linux vs a bounded one on Zephyr) is then just
  "hand a different `platform` at boot" — no `#ifdef`, no conditional global
  rebinding, no image surgery.

  *Distinction vs Toit containers.* This resembles the multi-version coexistence
  you get from Toit containers, but the mechanism and trade-offs differ. Containers
  are isolated processes — separate heaps, message-passing, independent lifecycle
  and over-the-air update, fault isolation. Newspeak modules live in **one heap**,
  compose by direct object reference (no IPC), and isolate by **capability scoping**
  rather than process boundaries: cheaper and more granular, but no fault/lifecycle
  isolation. They are complementary, not equivalent. One caveat specific to *this*
  dialect: because class references are statically bound (#1), version selection
  here happens at **boot/link granularity** (which module instances you construct
  and hand out), not hot-swappable at runtime — runtime class override is the
  deferred virtual-classes feature (#1's revisit trigger).

- **Class nesting gives real encapsulation.** Nested classes reach siblings through
  the enclosing module rather than a flat global, so a private helper class is
  genuinely private. In Smalltalk-80 every class is effectively public.

- **No ambient mutable image; deployment is deterministic.** Smalltalk-80's live
  mutable image is its great strength for interactive development and its liability
  for shipping ("works in my image"). Because names resolve through capabilities
  and (in this dialect) class refs resolve at compile time, the whole system
  solidifies to static C (Path A) or a frozen `.oimg` (Path B) and runs on a
  JIT-less interpreter with bounded memory and no global-dictionary lookups —
  reproducible and embeddable.
