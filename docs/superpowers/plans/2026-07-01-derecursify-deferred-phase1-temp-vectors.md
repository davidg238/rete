# De-recursify Deferred Lift — Phase 1: Indirect Temp-Vectors — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Move captured (closed-over) local variables off the fiber call-stack into heap `Context` temp-vectors, so a closure's variable storage is a single fiber-independent heap object — making cross-fiber shared capture correct by construction and giving upward-escaping closures a home that outlives the defining frame.

**Architecture:** Add a `struct Context` heap-object runtime (already reserved in `oevm/src/frame_abi.h`) with its own private vtable and precise GC tracer. The `.ns`→bytecode compiler (`ns-oevm/tools/ns_compile_oevm.py`) gains a capture pre-pass: any local referenced from a nested block frame is a *captured* local, allocated a `Context` slot instead of a stack register. A frame with captured locals allocates its `Context` in its prologue (`OP_MK_CONTEXT`); captured-local reads/writes emit `OP_LD_CTX`/`OP_ST_CTX` (walk the `Context->outer` chain `depth` times, index `slots[idx]`); non-captured locals keep fast on-stack `OP_LD_REG`. A closure captures its enclosing `Context` in a new runtime-only `struct Closure.captured_env` field, so variable access never touches the stack `home_ctx` link — which is left for the NLR `^`-return role only (relativized in Phase 2).

**Tech Stack:** C99 (oevm VM: `vm.c`, `gc.c`, `dispatch.c`, `kernel_boot.c`, `oevm.h`, `frame_abi.h`); Python 3 (compiler `ns_compile_oevm.py`, Model-A generator `solidify.py`, `.oimg` serializer `oimg_serialize.py`); the `.ns` test suite driven by `ns-oevm/tools/run_tests_oevm.py`.

**Interfaces:**
- Consumes: `context_alloc` (Task 1).
- Produces: opcode semantics later tasks rely on:
  - `OP_MK_CONTEXT dest, num_slots(src1), outer_reg(src2)` — `ctx->regs[dest] = context_alloc(src1, ctx->regs[src2] or closure->captured_env sentinel, ctx->gen_tag.tag32)`. Convention: `src2 == 0xFF` means "outer = the running closure's `captured_env`" (block prologue); otherwise `outer = ctx->regs[src2]` (nested context within a frame — not used in Phase 1, reserved) or `NULL` when `src1==0` path. Simplest Phase-1 convention: method prologue emits `outer = NULL`; block prologue emits `outer = closure->captured_env`. Finalize the encoding in Step 1 and document it in a comment above the handler.
  - `OP_LD_CTX dest, depth(src1), idx(src2)` — `cur = ctx->regs[CTX_REG]; repeat depth: cur = ((struct Context*)cur)->outer; ctx->regs[dest] = ((struct Context*)cur)->slots[idx];`
  - `OP_ST_CTX srcval(dest), depth(src1), idx(src2)` — same walk, `((struct Context*)cur)->slots[idx] = ctx->regs[dest];`
  - `CTX_REG` = the fixed register a frame stores its own `Context` in. Convention: the compiler reserves it and passes its index; the VM reads the context from a known register set by `OP_MK_CONTEXT`. To keep the VM stateless about which register, `OP_LD_CTX`/`OP_ST_CTX` take the context from a **compiler-chosen register** encoded — but that needs a 4th operand. Phase-1 simplification: reserve `CTX_REG = ` the frame's context register is always the value produced by `OP_MK_CONTEXT` into a compiler-fixed slot; encode that slot as the high byte of the instruction (bits 24-31, the free `src2`-adjacent field). **Decision to finalize in Step 1** (see note).

> **Design note for Step 1 (resolve before coding):** `OP_LD_CTX`/`OP_ST_CTX` must know *which register* holds the current frame's `Context`. Two clean options: (a) fix it by convention — the compiler always places the frame `Context` in the register immediately after the last arg/temp, and the VM hard-codes that rule from `method` metadata; or (b) add the context source register as an operand (the register-based ISA has `dest/src1/src2` = 3 bytes + 1 free byte in the 32-bit word — use the free byte). **Recommend (b)**: `OP_LD_CTX dest, depth, idx, ctxreg` packing `ctxreg` in bits 24-31. It is explicit, needs no method-metadata coupling, and matches how `OP_SEND` already uses all four bytes. Confirm the instruction packing helpers in `ns_compile_oevm.py` (`emit_ABC`) and the VM decode (`inst >> 24`) support a 4th field; if `emit_ABC` only packs 3, add `emit_ABCD`.
