# Walkthrough: Phase 5 - Stack Reification & Bytecode-Driven Non-Local Returns

We have successfully migrated the VM's Non-Local Return (NLR) mechanism from a legacy C primitive to a fully reified, bytecode-driven stack unwinding architecture. All integration tests are compiling and passing successfully.

---

## 1. Key Accomplishments

* **Guest Bytecode Unwinding:**
  - Implemented the guest method `MethodContext >> unwindTo:value:` and compiled it directly into the solidified image generated by `tools/solidify.py`.
  - Added support for symbol sanitization (e.g., converting `==` to C-compliant identifiers like `_eq`) inside the solidification pipeline.
* **Interpreter Loop Control Flow Support:**
  - Integrated a post-dispatch check in `run_interpreter` that detects if an unwind target is reached (`unwind_target_reached`).
  - Correctly exits recursive C interpreter stack frames when unwinding, propagating the return value back to the target context's caller.
* **Runtime Support Primitives (`src/vm.c`):**
  - Implemented `primitive_method_context_execute_cleanup` to execute optional cleanup closures.
  - Implemented `primitive_method_context_resume` to mark the unwinding target and register the returned value.
  - Corrected dynamic frame promotion in `primitive_method_context_sender` so that dynamic links (`prev_frame`) are promoted to the `MethodContextVtable` lazily on access.
  - Added global vtable routing for comparison operator `==` via `primitive_object_equals`.
* **Integration Verification (`tests/test_oevm.c`):**
  - Updated the NLR integration test to use the reified bytecode method instead of the legacy C primitive.
  - Registered all dynamic symbols as GC roots to prevent sweep reclaim.
  - Verified stack unwinding logic correctly compares target frames, executes cleanups, and resumes the target home frame.
