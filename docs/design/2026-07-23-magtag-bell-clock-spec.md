## The product

A MagTag that **strikes the ship's bells on the half-hour** and shows **VM stats** on the
e-paper, with the time kept honest by NTP.

## Architecture — the one decision everything follows from

**The local timer is authoritative for STRIKING. NTP only corrects BETWEEN strikes.**

A WiFi or NTP outage degrades the clock's *accuracy* but never its *reliability* — the bell
always rings. This is the right dependency direction for an appliance, and it is why NTP
failure is not an error path that needs handling beyond "record it and carry on".

Drift supports it easily: the Zephyr kernel clock runs off the systimer on the 40 MHz
crystal (the MagTag fits **no** 32 kHz crystal — see the board overlay), so ~10-50 ppm.
Over a 30-minute interval that is **0.02-0.09 s**. Half-hourly correction is generous;
hourly would do.

### Schedule

| Time | Event |
|---|---|
| `:25`, `:55` | NTP sync attempt, **at least 3 tries**, 5 min before the strike |
| `:00`, `:30` | **Strike** the bells (1-8 on the 8-bell watch, in pairs, lone final stroke if odd) |
| after the striking completes | **Repaint the panel** |
| any time | **Button 15 (BUTTON_A) repeats the last striking** |

### The collision that must not be reintroduced

**The panel repaint must NOT share a tick with the strike.** A full-panel e-paper refresh
takes *seconds and blocks*, and the bell is generated by a **hardware** oscillator — so a
repaint landing mid-strike does not merely delay the bell, it leaves the tone **droning**,
because the decay steps that silence it are stuck behind the repaint. Repaint *after* the
striking finishes (~4 s at eight bells, once the amp is muted). This keeps one reactor and
needs no async machinery — it is tuvm#94's original question 2, answered by ordering rather
than by architecture.

NTP at `:25`/`:55` already avoids the strike ticks; keep it that way.

## RAM budget — measured 2026-07-23, not estimated

Full stack = WiFi + SNTP + DNS + display + DAC, **no PSRAM**:

| `OEVM_HEAP_SIZE` | dram0 | result |
|---|---|---|
| 32768 | — | overflows by 5,056 B |
| 24576 | 98.47% | links, 3,392 B spare — the #53 knife-edge |
| **16384** | **94.67%** | **links, 11,840 B spare — CHOSEN** |

True arena ceiling ≈ **27.8 KB** (each arena byte costs 33/32 of dram0; the GC bitmap is a
separate static array outside the arena).

**16384 chosen for margin, not because 24576 fails.** This board has a history of tight
configs failing silently, and 98.47% is the #53 knife-edge again.

**THE OPEN RISK OF THE WHOLE PLAN:** 16 KB is *below* what tuvm#85 judged adequate ("32 KB
for a small/medium node"). Whether the node's working set fits has **not** been tested. This
is why stage 3 is staged separately — see below.

**PSRAM would roughly double the arena** (~48 KB) via `ESP_WIFI_HEAP_SPIRAM`'s 21,504 B
reclaim, but it **does not boot** — tuvm#96. It is an optimisation, not a prerequisite.

## Stages

Four flashable stages. Each is testable on the bench and leaves the board working. Do not
collapse them: stage 3 is where this can genuinely fail, and it must be reached with 1-2
already committed.

### Stage 1 — the nsl bell seam (gate 3 of #94; closes #86's "not done here")

Today the bell is boot-time C. Promote it to a prim so nsl drives it.

**Witness:** button 15 repeats the last striking. Self-contained, no time source.

**Files to touch (the prim-addition recipe, mirroring tuvm#88's display seam):**
1. `src/prim_ids.h` — `#define PRIM_pf_bellStrike 129`
2. `src/dispatch.c` — append `PRIM_pf_bellStrike` to the enum (~line 780), append
   `"bellStrike:"` to `PRIM_NAMES` (~line 835), and **advance the parity check**
   (line 846) from `PRIM_pf_displayRefreshRow` to `PRIM_pf_bellStrike`. Missing that
   last step silently misroutes every platform prim after the insertion point.
3. `src/platform.c` — host implementation + `extern` declaration in the target `#else`
   branch + the `case PRIM_pf_bellStrike:`
4. `zephyr/src/main.c` — `bell_target_available()` / `bell_target_strike(int n)`,
   refactored out of the existing `magtag_bell()`. Target impls live in `main.c`
   deliberately: a new `.c` file costs edits to **nine** enumerated source lists across
   two repos (tuvm#63).
5. `nsl-tuvm` kernel — a `Bell` class and a `platform bell` accessor. **A new kernel class
   needs an explicit accessor**; without it the class is unreachable from a node.

**Answer convention** — mirror the display seam: `nil` = no bell on this board (structural),
`SMI` = operational outcome (0 ok, 2 driver fault). Raises are written in nsl, not C.

**`bellStrike:` BLOCKS** — ~4 s at eight bells. Consistent with #88's four blocking prims.
Document it on the seam.

**Fold in the echo fix here** (see below). Arena stays 64 KB; no WiFi.

### Stage 2 — strike on the half-hour from a local timer

No network. Proves the bell always rings. Use the existing timer seam (`TimerNode.nsl` is
the reference).

### Stage 3 — VM stats + correction history on the panel

**Reordered ahead of WiFi on 2026-07-23, deliberately.** Stages 1-3 then deliver a
**fully working appliance** — the bell strikes on a timer and the panel shows stats — which
merely *drifts*. WiFi becomes an accuracy upgrade to something already working rather than a
prerequisite for anything. It also confines the RAM risk to a single stage: **stats without
WiFi runs at the full 64 KB arena**, so nothing before stage 4 is squeezed.

Grid is **portrait 12x18** — 12 columns is a hard limit; longer raises `#displayBounds`
(tuvm#89, and `rotate-180` is ON for this board). Sketch:

```
  tuvm  18:30
  ----------
  heap  9.2/16K
  gc        142
  up    3d04:12
  bells       5
  ----------
  ntp   -0.31s
  24h +0.9/-1.2
```

`heapStats` / `sysStats` prims already exist. The bottom block is stage 4's data — until then
show a placeholder or omit those two rows; do not block stage 3 on it. **Repaint after the
striking**, never on the same tick.

At 30-minute updates this is **48 refreshes/day**, comfortably inside the 180 s guidance, so
**no partial-refresh LUT is needed** and #94's original question 3 stays closed (see tuvm#89).

### Stage 4 — WiFi + NTP, arena down to 16 KB  ← THE RISK, AND IT IS LAST

Configs are **already written and link-tested**: `zephyr/prj_esp32s2_wifi.conf`.

- `sntp_simple(server, timeout, &ts)` does init/query/close in one call
  (`include/zephyr/net/sntp.h:161`) — no NTP state machine needed.
- Credentials: the git-ignored `prj_esp32_wifi.local.conf` (board-agnostic symbols).
  **`run.sh:249` only auto-applies it for `BOARD_ID=esp32`** — extend it to `esp32s2`.
- `CONFIG_ESP_WIFI_HEAP_SPIRAM` is **commented out** in that file and must stay so until
  tuvm#96 is fixed; selecting a heap whose backing region never came up is worse than the
  default.
- **Do NOT add `CONFIG_POSIX_API`** — it exports a bare `send()` that collides with oevm's
  own `send()` dispatch function.

Adds the bottom block of the stage-3 panel: last NTP correction, and min/max correction over
24 h.

**If the node will not run at 16 KB**, the honest options in order: trim the stack (drop
DNS and hardcode an NTP IP; drop SNTP and correct by button), or fix tuvm#96. **Because this
stage is last, a failure here costs the accuracy upgrade and nothing else** — stages 1-3 stay
shipped and working at 64 KB.

## Carry-over defect: the echo (fold into stage 1)

`bell_strike()` calls `dac_cw_generator_config()` once per envelope step, and that function
rewrites the frequency register and re-stamps phase — a **phase discontinuity mid-tone**,
i.e. a transient, three times per strike. It also re-measures the uncalibrated RTC-8M
oscillator each call, so the pitch micro-shifts too. Heard on the bench and initially
assumed impossible.

**Fix:** drive the envelope with `dac_ll_cw_set_atten()` alone (`hal/esp32s2/include/hal/dac_ll.h:161`),
which touches only `SENS.sar_dac_ctrl2.dac_scale1` — no frequency, no phase. The HAL include
path is global (`hal/espressif/zephyr/esp32s2/CMakeLists.txt:12,45`), so `hal/dac_ll.h` is
reachable from app code. Call `dac_cw_generator_config()` **once** at the start of a strike,
then step attenuation only.

## Hard-won constraints (do not rediscover)

- **The amp needs ~50 ms to settle.** GPIO16 high → wait → drive. Cost three builds in #86.
- **Notes must be long.** 160 ms is inaudible at `rc=0`; 500 ms is loud.
- **440 Hz, and the low end is the good end.** 1760 Hz sounds bad. This is the *opposite* of
  what a square-wave-harmonics argument predicts.
- **GPIO17 is both `LEDC_CH0_GPIO17` and `DAC_1`.** Never enable `CONFIG_PWM` and the DAC
  together without disabling `&ledc0` — the failure is `rc=0` and silence.
- **`dac_esp32_init` FAILS on this part (tuvm#95)** — take the pin enable from
  `dac_output_enable()`, not `dac_channel_setup()`.
- **Driver failures are SILENT**: these builds have `CONFIG_PRINTK` but not `CONFIG_LOG`, so
  every driver `LOG_ERR` compiles to nothing. Add `CONFIG_LOG=y` + `CONFIG_LOG_MODE_MINIMAL=y`
  (~1 KB) before debugging any driver that misbehaves for no stated reason.
- **Flashing is manual** (BOOT0 + RESET). The PL2303 UART header on `/dev/ttyUSB0` is the
  only console, and **opening it does NOT reset the board** — so a handle can be held across
  a flash. Hold exactly **one**: two readers split the byte stream and each silently drops
  lines, which reads as missing output rather than contention. (Hit twice on 2026-07-23.)
- **`space drain` is required**, not just `platform pumpEvents` — a reactor loop without it
  enqueues button presses forever and runs none of them (`MagTagDisplayNode.nsl`).
- **`whenever:do:` is the only subscription selector**; the wrong one compiles clean and
  kills the node at run time.

## Dropped from scope

- The clock face (superseded by stats).
- The RGB/NeoPixel flash — would need `spi3` or I2S; this Zephyr tree has **no RMT driver**
  and `spi2` is the e-paper's.
- Per-sample additive synthesis — the 4-step hardware envelope reads as a strike, so this is
  unnecessary.
