## 2. Terms

> **NAME COLLISION — read first.** In this repo's older documents "v1" means the Toit-era protocol (archived 2026-10-02 at `protocol/archive/PROTOCOL.md`) and the nsl space-sync protocol is informally "v2". David, 2026-10-02: that protocol is legacy, had one user, and has no claim on the numbering. So **"1.0" in this document does not mean protocol v1**, and rete's version numbers are its own: 0.x until the freeze, 1.0.0 at it. This document says **surface 1.0** for the first frozen surface and **the next surface** (or surface 2.0) for its successor, and never uses a bare "v1" or "v2". The older documents still carry the old words.

### 2.1 People and machines

| Term | Meaning |
|---|---|
| node | One device running the VM and an nsl program. Everything it knows about the outside world arrives over the wire. |
| porta | The Go program that stores each node's data and serves the operator. It is the northbound half of rete (`~/workspace/rete/porta/`). |
| gateway | Another word for porta in its role as the node's counterpart. In this document gateway = porta. |
| fleet | All the nodes one operator runs. Every node that exists today is one David can reach and reflash, which is what "no fleet to protect" means in the posture. |
| external user | Someone who is not David and runs rete on hardware David cannot reflash. The posture "expires" when the first one exists. |
| publication / going public | Making the repository and its documented behaviour available to external users (rete#79, `docs/next-steps-overview.md` Part 2). |
| flag day | A change that works only if both ends change at the same moment. Today every wire change is a flag day, and that is acceptable only because David reflashes everything. |

### 2.2 The freeze vocabulary

| Term | Meaning |
|---|---|
| surface | The set of names, shapes and behaviours that another party's code or device depends on. If it changes, their code or device can stop working. |
| contract | The written statement of the surface. In rete the wire contract is `protocol/` and the machine-readable part is `protocol/MANIFEST.cddl`. |
| breaking change | A change after which a correct existing dependant stops working. Example: rete#197 renamed `bootId` to `bid`, and a node and gateway on opposite sides of the rename could not talk. |
| additive change | A change after which every existing dependant still works. Example: rete#190 added `sys/cheap` as a new record at a new path instead of adding fields to an existing record; nodes not publishing it were unaffected. |
| freeze / frozen | A promise that the surface will change only additively. After the line, a breaking change is a new surface, not an edit. |
| freeze line | The moment and the artifact that mark "from here on, frozen". Here it is a hash (§5). |
| surface 1.0 | The surface as of the freeze line. Its name, not a protocol version. |
| burn list | The breaking changes that must land before the line (§6). "Burn" because after the line they cannot be done cheaply. |
| gate | An automated check that fails the build or the test suite. A rule without a gate is a hope. |
| pin | A hash baked into a build at build time so the build can say which contract it was made against. |

## 4. Why freeze, and why now

| Reason | Evidence |
|---|---|
| The posture inverts on the first external user | rete#253 body: the zero-compat posture "has an expiry date: the day rete has one external user, it inverts". |
| Breaking changes after a community exists cost far more than the change | rete#253 cites Elm 0.18 to 0.19: resentment "out of proportion to the changes themselves". |
| Corrections beat accretions only while compatibility is free | `CLAUDE.md` Design posture: "each field was added *beside* what was there rather than *instead of* it". After the line, beside is the only option. |
| A mixed fleet already happened | rete#197: two boards, two label sets, and the gateway could serve only one. |
| Wire changes are queued now | Every burn-list item in §6 moves the hash; landing them after the line means each is a version event. |

**Why a hash and not a version number.** The rete#200 amendment: the record catalogue already has a version, the manifest hash, and every node already publishes it at `obs/build.man`. A `v` field in the envelope would be a second mechanism for a frame that has changed once in the project's life. "Who is still on the old one?" is already a query on `obs/build`.

**Why now.** Every item on the burn list is decided and none touches an external user. The cost of landing them is one sequenced deploy (§6). The cost after the first external user is a flag day they must be part of.

| branch `118-node-id-factory-address` | `d7eefc871e538b77…` | `sha256sum protocol/MANIFEST.cddl` |

Neither is the 1.0 hash.

**What happens today when a node's pin differs from the gateway's: nothing at runtime.**

| Check | Where | When |
|---|---|---|
| Build pins whatever porta serves; if porta is unreachable it falls back to the repo copy, loudly, stamped `source=repo` | `pin_manifest.py:11-13,69,79` | Build time |
| Provision gate refuses when the build's archived pin differs from the served manifest ("pin mismatch … rebuild") | `protocol/tools/check_provision.py:22-38` (comparison at line 35) | Provision time |
| porta loads one manifest and gates every write against it, regardless of the node's pin | `serve.go:117` (`StoreManifest`), `manifest.go:8-14` | Every write |
| Nothing reads `obs/build.man` and compares it | `rg` over `porta` Go sources finds no reader; `man` is stored as an opaque value | none |

So a node built against another manifest connects, publishes its pin, and is judged only by whether each record passes porta's store gate (a first-byte class check). The pin is a label, not a handshake. This is the fact §9c item 4 builds on.

**What cutting the line means operationally (PROPOSED — not decided).** One commit that changes nothing but records the hash as surface 1.0 in this document and in `PROTOCOL-NSL.md` §8, plus a git tag. After it, any change to `MANIFEST.cddl` is either additive or a new surface (§9b).

## 7. What could be missing (PROPOSED — not decided)

These are findings of writing this document. Each ends with options. "Decide later with a named trigger" means writing down the event that forces the decision.

### 7.1 The language half has no machine pin
The manifest hash covers the wire only. Nothing fails when a channel verb is renamed or an accessor is removed, except whichever suite test happens to use it. The freeze line as decided is a wire freeze line.
**Options:** freeze it (generate a list, gate on it), declare it unstable, or decide later with a named trigger.

### 7.2 The accessor set is unenumerated and larger than "a set to freeze" suggests
90 public selectors (§3E), including board-specific hardware, test seams and kernel-internal helpers. Each needs a fate: frozen, unstable, or should not be public.
**Options:** freeze a core group, declare the rest unstable, or make test seams non-public.

### 7.3 Three documents disagree about the channel verbs
rete#253 lists six verbs and writes `out:`. The kernel has fourteen public methods on `Channel` and `Space` (§3C), and the real selector is `out:value:`. `programming_with_nsl.md` §4 teaches "The four verbs" including `chan take: rel` (line 168), which is not public, and cites `.ns` test paths. Per the repo's posture, a disagreement between documents of record is a finding to resolve, not to route around.
**Options:** the kernel is right and two documents are edited; or the kernel changes. See decision 11.

### 7.4 The language itself
The grammar (`nodus/nsl/docs/NEWSPEAK_DIALECT.md`, `nodus/nsl/grammar/ns.ohm`) and the standard classes' protocols (List, Map, Record, Protocol, Timers, Supervisor). An external user's program depends on these at least as much as on the channel verbs. rete#253 names neither.
**Options:** freeze the grammar and a named class list; declare unstable; decide later.

### 7.5 The image format
Under Model B the VM is flashed once and `.oimg` images are pushed. The loader refuses any other format version (hard-coded 10 at `nodus/oevm/src/oimg_loader.c:140`) and any registry version that differs from the firmware's (line 144). Compiler to VM is a second wire with two version numbers, and it is not in rete#253's list.
**Options:** freeze it; declare it unstable because compiler and VM ship together; decide later.

### 7.6 The bulk plane
Fixed binary framing on exchange port + 1 (`PROTOCOL-NSL.md` §5.3). Not CBOR, not in the manifest, so not under the hash.
**Options:** bring it under the manifest's coverage, declare it unstable, or decide later.

### 7.7 The transport
Today it is plain UDP carrying CBOR. CoAP (a lightweight web-style protocol) is the ratified direction (`PROTOCOL-NSL.md` §8, 2026-07-15), unbuilt, gated on a measurement of DTLS (encryption) memory use. If it lands after the line it is a breaking change the hash cannot see. The node's gateway port is a source constant in node programs (`porta/docs/GETTING-STARTED.md:125`; the tutorial binds udp 16969 and 16970, `docs/tutorials/03-porta.md:22`).
**Options:** do it before the line, state surface 1.0 as UDP, or decide later with the DTLS measurement as trigger.

### 7.8 Authentication
rete#291: there is no authentication on the wire. Adding it later changes the envelope or the transport.
**Options:** land before the line; or state plainly that surface 1.0 is unauthenticated and that authentication is a surface 2.0 event.

### 7.9 Shapes the manifest deliberately does not pin
`goal/forward` and `obs/forward` have no rule (manifest header). `App.arguments` is an open map (RECORDS §6 q2). Enum fields are open symbols unless the catalogue enumerates the set (manifest header). A frozen hash freezes the text, including its holes.
**Options:** pin them first, or accept the holes in writing.

### 7.10 Numbers that are contract but live in prose
Size caps (RECORDS §2.2, "a first cut" per RECORDS §6 q1), the decode depth bound, the node id format (12 or 16 lowercase hex: `docs/design/2026-09-11-node-identity-hardware-rooted-design.md` and its 2026-10-02 addendum). A search of `MANIFEST.cddl` for the caps, depth and node id finds none of them.
**Options:** pin them in the manifest or a sibling checked file; declare them tunable; decide later.

### 7.11 Behaviour that is contract but has no shape
Kind fixed by first write; dedupe by seq and high-water; the liveness rule; reaction order is registration order with no dedupe; run-to-completion; the `sys/` reserved namespace; the "frozen substring" convention for runtime error texts (rete#265: "freeze the substring, enrich the rest").
**Options:** list each as frozen with its owning test named; declare unstable; decide later.

### 7.12 RECORDS §6 open questions 1 to 5 are still open
Caps, `arguments`, cursor persistence, `Metric.value` int versus float, per-path versus snapshot push. Freezing with them open means each resolves later as an accretion.
**Options:** per question, answer before the line, or accept as-is (decision 7).

### 7.13 porta's operator surface
The CLI verbs (`porta/docs/CLI.md`) and the sqlite file. Named in the rete#253 comment of 2026-09-16 as non-wire; no fate given.
**Options:** declare unstable; freeze the CLI only; decide later.

### 7.14 What "1.0" is attached to
There is no version number anywhere but the hash (the `LICENSE` is Apache-2.0 since 2026-10-11, rete#368). A git tag, the hash alone, or both?
**Options:** tag plus recorded hash (§5); hash only; decide at the cut.

## 8. Limitations of this approach

| Limitation | Consequence | Mitigation |
|---|---|---|
| A hash is an identity, not a compatibility relation. Any byte change moves it, including an optional field, a new record, a comment typo or whitespace | After 1.0, "is hash X compatible with 1.0?" has no mechanical answer | None yet; §9c items 2 and 3 |
| It guards shape, never meaning. rete#190: both ends agreed on `format_version` 9 and disagreed about the ABI | A matching hash does not mean matching behaviour. rete#200: "a version guards the envelope, never the meaning of the fields" (a row in `review/tests/CLAIMS.md`) | Tests only |
| It covers only what is in the file | §7 items 1, 5, 6, 7, 10, 11 are outside it | None |
| Deep shape validation is at build time. porta's store gate is a first-byte class check; "deep shape validation stays at the zcbor gates" (`manifest.go:8-14`) | A node built outside this repo's gates can send a mis-shaped record that porta stores | None |
| Field closure has two readings. RECORDS §5 (2026-08-25) retires "consumers ignore unknown fields" and says the gates refuse. rete#200's 2026-09-16 amendment says field closure is relaxed at runtime on both ends and the statement is still to be written into RECORDS §1 | Both are true (gates closed, runtime tolerant), but until the paragraph lands the documents read as contradictory | rete#200 (b) |
| The published pin is truncated to 8 bytes | An identifier, not a security property | None needed unless pins become trust |
| The trigger is an event, not a date: "the day rete has one external user" | Nothing detects that day | None; this document is the reminder |
| Frozen is not proven. The caps are "a first cut" (RECORDS §6 q1), no node has yet run outside David's reach, OTA on Zephyr is inert (rete#233) | The surface can be frozen and still wrong | Measurement; see decision 7 |
| A freeze is only as strong as the gate that fails when it is broken | §7.1: half the surface has none | Decision 1 |
| No runtime mismatch detection (§5) | Wrong-contract nodes are found by symptoms | `obs/build` query |

### 9a. What the records already say (decided)

|---|---|
| RECORDS §5 | A breaking change gets a new record name at a new path. Optional fields keep their meaning. There is no version field; the pin is the version. |

| rete#200 comment | `v` in the envelope is deferred. Trigger: "the first rollout that cannot be completed inside one maintenance window". |
| rete#200 body | Of three mismatch behaviours (reject, negotiate down, tolerate) none is chosen. N=2 concurrent versions "nearly always". |

### 9b. Two kinds of change after the line

| Kind | Examples | Effect |
|---|---|---|
| Additive | New path; new record; new optional field | Surface 1.x. No flag day. The hash still moves. |
| Breaking | Rename, retype or remove a field at an existing path; change a path's kind, class or direction; change an envelope shape; change the value encoding; remove or rename a verb or accessor | Surface 2.0 |

### 9c. What has to exist before a surface 2.0 is possible

| # | Needed | Exists today? | Issue |
|--:|---|---|---|
| 1 | The field-closure statement and its two gates. Without it additive change is not safe either. | No | rete#200 (b) |
| 2 | A manifest diff classifier: takes two manifests and says additive or breaking, run as a gate. This turns the hash from an identity into a compatibility relation. | No | none |
| 3 | A record of lineage: which hashes are surface 1.x, compatible descendants of the 1.0 hash. Could be a list in `protocol/`. | No | none |
| 4 | A gateway that serves more than one manifest at once, or a stated rule that it never will. | No: porta loads one manifest (`serve.go:117`) and does not compare node pins (§5) | none |
| 5 | Working OTA. A node that cannot be reflashed by hand cannot cross a breaking change without it; the federation doc §5 says the same. | Partly: the host OTA exists, the Zephyr backend is inert | rete#233 |

| 7 | A declared support window: how long surface 1.0 is served after 2.0 exists. | No | none |
| 8 | For the language: a deprecation path (a compiler warning for a deprecated selector; the old selector kept for the window). The image format's two version numbers are a hard refusal, not a negotiation (§7.5). | No | none |
| 9 | A name for it. "v2" is taken (§2 collision note). | No | none |

**Cheapest first.** Items 1 to 3 make 2.0 cheaper later and are small now. Everything else waits for its trigger. This document does not design the mechanisms.
