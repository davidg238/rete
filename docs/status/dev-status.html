2026-08-31 — an aside, filed and not worked: cooperating agents (#287, P3). Raised by David off-shift and explicitly not a priority change; #281 remains the focus and was not advanced. Three findings are worth carrying because they were established by reading rete source rather than estimated. The VM is a process, not an object — vm_stack, heap_base and builtin_registry are file-scope globals and there is no vm_new(), so one VM per OS process. OEVM_HEAP_SIZE is compile-time only (nodus/oevm/src/gc.c:18), so a small agent is a rebuild, not a flag. And the ceiling on any many-agent scheme is not RAM but porta's serial UDP loop (porta/internal/wire/server.go:300-329): one goroutine, read → synchronous sqlite write → reply, no worker pool — orders of magnitude below the RAM ceiling, and correct for a real mesh where the radio is the bottleneck.
