  2. #272 — porta judges ARRIVAL where the node judges PROGRESS. The widest gap, and it is #269's own defect one layer up: verdictFor tests now - last_seen, a proxy for health in exactly the way mailbox depth was a proxy for progress. The progress counter is already on the wire — obs/health.wak is the bridge's tick count, published every check-in and stored in cells. The fix adds no field and no mechanism. Modelled 2026-08-28 (fac6403): "advanced" has two readings and only one works. As a between-sweeps delta it still fails — the counter advanced early in a window the node spent wedged, which is #269's aliasing one level up. As an age (now - last_progress ≤ bud) it is the right signal, and the reboot loop falls out of it with no boot_id join. Next action: adopt the age rule in verdictFor — but not before #273 is decided, because the age rule's staleness bound is bud + SweepTick.
  3. #273 — four deadline numbers that nothing derives from each other. cad, the wedge deadline (WEDGE_SLACK, in C), bud (cadence × 8, in nsl) and SweepTick (a constant, 30 s). They happen to agree today and nothing announces it when they stop — and the agreement is a coincidence of configuration: the wedge deadline derives from the shortest declared timer period, not from cad, and porta is never told it. The model now names the relation: bud + SweepTick ≤ the deadline the node enforces — green over 3.17M states, non-vacuous. Today that reads 16000 + 30000 = 46000 against 16000 ms, off by 2.9×. A design call, and it is David's: which number is the source of truth. A five-point proposal is recorded in the liveness design doc (addendum 2026-08-28).

What changed since 2026-08-26

  • #269 — the detector was rebooting a healthy node. It judged the pulse mailbox's depth at a sampling instant, which aliases against the workload: at cad 2000 under a silent uplink the mailbox empties for ~1 s inside every 4.007 s tick while the observer samples every 1001 ms, and a 3 ms beat walks the one sample that catches the empty window out of it. Fixed by judging progress (pulse_drained()). Caught by the new porta-silent scenario on its first run.
  • #270 — closed, and it exonerated the detector. All 58 archived deadline=16000ms events walked: 49 real wedges (18.2 s of silence against a 2 s cadence; 35 also read reactor=NOT-ADVANCING — the #222 prim-cache spin), 2 deliberate, 7 false trips all from the one session that found the bug. No attribution overturned.
  • The wedge verdict now runs on the host. It lived in zephyr/src/observer.c, which no host gate compiles, so every bug in it had cost a board cycle. Split into src/observer_core.h; the test sweeps 30 015 timing combinations in 70 ms and carries the old buggy predicate in-file, requiring it to fail. nsl suite 278/0, every aux gate PASS.
  • The contract was diagrammed and model-checked (TLA+). Eight labelled holes → three defects → #272, #273, #274. The model was wrong first and the board corrected it: a delivered tick is max(cad, work), not cad + work — which predicts both of #271's measured rows.
