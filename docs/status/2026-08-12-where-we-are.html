02/31

the model

The one idea worth holding

Everything else is detail hanging off this.

A node owns a tree of paths

The operator writes what they want under goal/. The node writes what it sees under obs/, tel/, sys/. porta holds a mirror of that tree.

Convergence is not a mechanism

goal/X versus obs/X is a tree diff. The desired-vs-observed view and the self-heal loop are the same query — nobody had to build a reconciler.

There are no verbs on the wire and none in the store. porta put is a write to a path; porta get is a tree read. Adding a feature adds a path — not a table, not an endpoint, not a command. That is the decision the whole rewrite turned on.

north

porta — the gateway half

Latin for gate. Go. Runs on gw85224-01. v1 was deleted in one commit and rebuilt.

Working

  • Four tables where v1 had nine — nodes, cells, events, exchanges.
  • The wire is a pure Handle([]byte) []byte with a thin UDP loop around it.
  • A hand-rolled CBOR codec, golden-tested against the node’s own output. Not a library, on purpose.
  • The CLI — serve, get, put, log. Verbs live here and nowhere else.

Not working

  • #180 — the store does not pin a path’s kind, so a wrong-kind write is legal here and fatal there.
  • #176 — a port collision on startup becomes a gateway outage.
  • Docs are stale — CLI, GETTING-STARTED and ARCHITECTURE still describe v1.
  • #171 — /health still reports a v1 field that no longer exists.

Operationally: porta.service is disabled; v2 is hand-started from ~/porta-v2. Restarting it costs every node an outage.

10/31

#201 / #202 · safety

RED — the bell can stick on

The only issue here that can hurt something outside a computer.

11 Aug, 23:01
A flash of c6-bell failed. esptool reset the chip into the ROM downloader and lost it. The striker stayed energised and the bell rang continuously for two minutes, at eleven at night, stopping only because your son unplugged the cable.

Why it happens

The ROM downloader drives no GPIOs. Whatever state the pin was left in persists, unbounded, with no software anywhere in a position to intervene — the VM is not running.

What closes it

#202: bound the on-time outside the VM. AC-couple the drive so a stuck pin cannot hold the load on. #201 asks the narrower question first — does a pull-down resistor close the two-minute case? One meter reading answers it.

Your own priority correction, 12 Aug: “I don’t care about 1 sec sound at flash, it’s when it sticks on I care.” That is what #202 is scoped to.

11/31

#199 · liveness

RED — a node can die while reporting itself healthy

11 Aug, 15:38
A node whose frames the gateway rejected ran out of GC arena and halted in 2 min 37 s. For all 46 ticks before it died it printed misses 0 — the number that is supposed to mean “healthy”.

Half of it is fixed

The allocation leak behind the death closed with #161’s fix. On the same harness: dies at 114 s before, alive at 900 s / 450 check-ins after — which is the control’s own count, so refused and accepted nodes now last equally long.

Half of it is not

The observability half. misses counts replies that did not arrive; it cannot see a reply that arrived and was rejected. A node being refused looks identical to a node that is fine, right up until it halts.

The general shape, and it recurs: the instrument agreed with the happy case and had no opinion about the failing one. That is the theme two slides on.

12/31

#180 / #206 · the store

AMBER — the gateway store can brick a node

Two independent ways a perfectly legal write to porta silently kills a node at every boot afterwards. Reflashing does not help. Only editing the store does.

#180 — wrong kind

The store does not pin whether a path is a cell or a stream, so a put of the wrong kind is accepted. The node it reaches hangs.

#206 — right kind, wrong count

More than one replayable dbg/req profile request wedges the node when the window ends. Correctly typed rows. Proven four ways, including by deleting two rows and watching the node recover.

Why this is worse than it sounds: a cold boot replays every request ever written, so the hazard is permanent and arms itself on the next reset — long after whoever typed the command has forgotten. Driving a profile window is itself the thing that arms #206.

pick one

Three honest options for what’s next

safety

Close the actuator hazard

#201 then #202. One meter reading, then a hardware change. Small, bounded, and it is the only open item that can affect something physical at 11pm.

trust

Make the instruments honest

#199’s observability half, #180 and #206. The pattern that has cost the most time. Nothing new gets built on a base that reports itself healthy while dying.

reach

Push the story outward

#198 gatekeeper (agent-facing queries), #181 (move the bench to the gateway host), #79 (is there a route to market at all). Everything here is optional and none of it is blocked.

These are genuinely alternatives, not a sequence. The first is hours; the second is days; the third is open-ended.
